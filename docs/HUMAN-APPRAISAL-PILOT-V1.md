# 中文逐事项双人盲评试点协议 v1

## 目的与边界

请独立评价给定事项证据，不评价模型、不猜作者预期，也不讨论“该不该存档”的软件策略。每项按四个不同构念评 0–4 或 `X`：重要性 I、用户表达情绪强度 E、独立重复 F、新近度 R。四项不得互相代替。当前表是**量表措辞与评审流程试点**，不是项目金标准：样本只有 12 项、10 段合成中文对话，分数不能用于训练、性能结论或宣称人评一致性。

两位评审分别收到 `blind-form-01.csv`、`blind-form-02.csv` 中的一份；题序不同。不要互看、讨论或查看模型结果及资格报告中的模型分数。完成后原样交回两份 CSV。主持人用比较器检查字段、刺激完整性、空值和分歧；不自动裁决、不合并分数。样本含多个事项的对话会拆成独立事项行，但保留整段对话上下文。

## 共通规则

- 只根据“逐轮对话角色时间和原文”“事项用户原文证据”及提供的 UTC 时间评分。`事项`是待判断的目标，不是标签。引文是用户原话；助理说出的内容不变成用户事实或情绪。
- 每项每维独立给整数 `0`–`4`，或 `X`。`X` = 当前材料不足、来源/归属不清或无法判断；留空 = 尚未完成。二者都不是零分。
- 若对话明确支持某维为零，填 `0` 并写明证据；若没有足够证据确定是 0 还是非 0，填 `X`。不得为了填满表格猜测。
- 四列“依据或X缺失说明”必须逐项填写：写出具体轮 ID 和短引文，说明它为何支持该分；`X` 时说明缺少什么证据。I/E 使用用户原话与上下文，F 指出计入的独立用户轮，R 指出末次有效用户提及时间及评估时间。F/R 的提及数和时间间隔已从刺激机械计算并列出，仅是输入证据，不是 I/E 标签，也不替代评审核查事项归属。不要只写“见上下文”。
- 事项版本不可互相累计：通知明确更正后，K39（旧群邮件规则）和 K88（留言板新规则）是不同版本，分别看其所附证据。一次更正不会把旧版本自动算作新版本重复提及。
- `retrieval` 轮、assistant 轮、引用/转述的台词都不是新的独立用户提及。用户在同一消息重复措辞仍是一轮。不要用叙述次数推断事实的重要性或情绪强度。
- 对本试点的合成/虚构场景，仍按“这段证据表达了什么”评分，不把台词当成用户经历。若无法确定说话者是在表达本人感受还是照稿念，对 E 填 `X` 并解释。

## 暂定操作锚点

下列锚点只为让两位评审使用同一套试评规则；特别是 F/R 分档尚未经过独立量表验证。评审可在依据栏记录锚点覆盖不到的情形，不能私自改量表定义。

### I：忘掉该事项对未来决定、约定或理解的代价

- `0`：证据明确表明只是虚构/一次性内容，且对未来约定、行动或理解无后果；或该事项明确不重要。
- `1`：短暂、低后果的偏好/细节；忘记后容易补问，几乎不影响行动。
- `2`：以后可能有用的背景或偏好；忘记会造成轻微不便或重复沟通。
- `3`：当前有效的具体约定、边界、稳定偏好或进行中事项；忘记可能导致明显误解、返工或错过安排。
- `4`：证据显示忘记可能导致严重、安全/隐私/法律/财务后果，或不可逆的重要行动错误。
- 无法判断是否真实、有效或有未来后果时填 `X`。语气平静不降低重要性；出现次数多不自动升 I。

### E：用户本人针对该事项表达的情绪强度，不分正负/类别

- `0`：可归属给用户的原话明确平静、中性，未见情绪表达。
- `1`：轻微情绪词或轻度态度，表达克制。
- `2`：清楚且中等强度的情绪表达。
- `3`：强烈、显著的情绪表达（如强烈措辞、明确强烈身体/行为反应）。
- `4`：极强、持续/反复或明显压倒性的情绪表达。
- 无情绪词不自动等于明确中性：若证据不足判定 0 或更高，填 `X`。角色台词、助手语气或他人感受不能评分为用户 E；归属不清填 `X`。积极与消极只看表达强度，不改变分档。

### F：该事项/该版本被用户独立提及的次数

仅统计表中截至“评估截止 UTC”的有效用户轮，每个用户消息对同一事项版本最多计一次。先写出计数，再按以下试点评分映射：

- `0`：没有独立用户提及；
- `1`：一次；
- `2`：两次；
- `3`：三至四次；
- `4`：五次或以上。

同一消息重复同一句、assistant 复述、retrieval 命中不增加计数。事项版本范围不清、缺少应有对话证据或无法辨认用户轮时填 `X`。这个分档只是预先公开的试点映射，不是已验证的心理量表；CSV 已提供程序核对后的独立用户轮数，仍请独立核查引文归属与计数依据。

### R：有效用户末次提及距评估时点的时间新近度

按表中 UTC 末次用户提及时间与“评估截止 UTC”计算间隔；越近分越高。暂定固定分档：`4` = 0–1 天；`3` = >1–7 天；`2` = >7–30 天；`1` = >30–90 天；`0` = >90 天。没有该事项的用户提及，不得把“无”当 0；填 `X` 并说明。若时间戳缺失/不合法或事项有效版本无法确定，也填 `X`。重新检索或 assistant 重述不刷新末次提及时间。

## 本批刺激注意事项

本批对话是专门构造的诊断刺激，不是真实用户经历，也不含任何评分答案。每项的用户提及计数与 UTC 时间由原始刺激字段机械推导，供核对证据输入；它们不提供 I/E 的答案。相同表面话语在不同上下文中用于检查 I/E 是否引用上下文；“两份都要签”等配对用于检查 I 不能仅看一句话；台词与本人感受配对用于检查 E 的说话者归属；K71/K47/K06/K39/K88 等条目用于核对重复、缺失和时间口径。不要把这些设计意图当成预期分数。

## 完成检查与回传

1. 每份表应有 12 个唯一编号；不得改动刺激、时间、引文、版本、证据 ID、计数或 SHA-256。
2. 四个评分列逐行填写整数 `0`–`4` 或 `X`，不使用小数、范围或文字替代评分。
3. 四列依据说明均填写；若评分为 `X`，写出缺失/歧义证据。评审不同意试点锚点时，在依据中说明，不得改表头。
4. 两位评审独立完成并分别提交，不互换文件。主持人之后运行：

```bash
python3 spikes/appraiser-pilot-v1/review_packet.py compare \
  <blind-form-01.csv> <blind-form-02.csv> --out <new-comparison.json>
```

比较器会拒绝同一路径、重复/缺失编号、刺激证据变更和非法分值；理由或评分未完成时会保留空缺并报告未完成数，不会把缺失改成零。输出仅描述一致/分歧和 `X`，不宣称一致性等于构念效度。不要覆盖已有提交或比较结果。

## 结果解释

12 条刺激仅能发现说明不清、证据核验错误和严重分歧，不足以稳定估计评审可靠度。保留两人的原始分数及理由；讨论产生第三份裁决记录时须保留原始提交，明确标为 adjudication。只有经过量表修订和更大、按对话/事项族隔离的数据采集，才能考虑项目量表训练。重要性和情绪需要独立中文项目标签；重复次数与时间间隔可由有证据的用户轮/UTC 输入确定性计算，是否映射成 0–4 需由标注研究验证。
