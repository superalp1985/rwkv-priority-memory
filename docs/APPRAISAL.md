# 模型如何判断这件事值不值得记

**判断单位是一件事，不是一整轮的气氛。** 评分问题是：“将来与这个用户交谈或行动时，如果没有这条信息，会不会误解他、错过约定，或按已经过时的规则做事？”用户不说“记住”也要判断。它不是给模型自己刚才的回答打分，不是对事实真假的判定，也不等于测到了人的意识。

## 同一时点，三种评估状态

每轮都截在用户说完、助手尚未回答时。三组使用同一模型、候选、用户引文、UTC 时钟、量表、tokenizer 和工作卡预算，区别在于从哪里开始评分：

- `read_only`：复制完整真实对话的 state；分支打分后丢弃，不写卡。
- `replacement`：从空 state 重放最近三个完整问答和本轮用户发言，再放入上一轮仍有效的工作卡。下一轮重新构建。
- `feedback`：继承上一轮评估 state，实际对话各输入一次，从未被评分提示污染的边界写入新增卡；已写入的卡被更正或淘汰时，从不含卡的真实对话 state 恢复，再写入有效卡。

这里替换的是**运行时评估 state**，不是修改模型权重，也不直接改变前台回复。四个问题各自从同一冻结边界的副本续算，下一事项看不到上一事项的评分提示。只有有效的卡片内容可以进入后续反馈状态。[原生读写接口](STATE-INERTIA.md)

## 四个独立判断

| 维度 | 模型判断什么 | 给模型的证据及边界 |
|---|---|---|
| 重要性 | 忘掉对以后的决定、约定或理解有何代价？ | 平静的长期约定仍可很重要。不要用语气或次数代替。 |
| 用户情绪强度 | 用户针对这件事表达得有多强？ | 只评强度，不分种类或正负，不把台词或助手的语气算到用户身上。 |
| 重复提及 | 不同用户轮是否持续强化同一件事？ | 提供轮次、去重次数和原文短引。同一消息内反复措辞、助手复述、检索均不强化；否定和更正要结合语境。 |
| 新近度 | 最后一次真实提及，相对当前对话的时间尺度有多近？ | 给出 UTC 提及时间与评估时间。重读不刷新时间，不使用固定半衰期替模型给分。 |

固定权重探针在每个问题后比较 `0` 到 `4` 以及 `X` 六个标签的 logits，取最高者；softmax 只在六个标签内归一化，不是对人类同意率的估计。数量、时钟和引文是证据，等级来自模型。四项归一化后等权排序，同分按事项 ID 排序。引文由夹具提供并核对确实是用户原文的子串；模型没有生成理由，也未证明释义真实。具体英文提示见 [replay_runtime.py](../probes/replay_runtime.py)。

任何一项为 `X` 就标待评，不把缺失伪造为零。仅同一有效版本可以暂沿用上一组完整等级；新事项没有评级时不入卡。回放里的更正由夹具给出旧版本 ID；强制旧卡退出不等于模型自行理解了更正，更不等于抹掉历史原文。运行异常报错，不伪造缺失的输出。

## 持续状态：容量不足才淘汰（新实验规则）

- **默认延续。** 继承上一轮 state。工作卡还有空间时，需记的不同事项直接加入；仅分数或排名改变不淘汰、不重排。即使已满，没有必要的新写入也不淘汰。
- **需要腾位时才用分数。** 新事项确实需要进入工作记忆且放不下时，按已有有效事项的综合留存优先级从低到高腾位，够用即停。四维相对权重待对照实验校准，不把现行等权写成结论。
- **明确更正不等容量。** 同一事项、同一适用范围的约定被明确更正后，立即以新版本为准。例如平静地确认改到十点，不应因旧九点的情绪强度更高而继续按九点执行。这改变的是版本有效性，不是用新事项挤掉别的记忆；旧版本原文仍可按需查回。

原生 RWKV state 是每步都会更新的固定形状张量，没有可枚举的事项槽位或可直接读取的“已满”标志。实验先用工作卡预算定义可观测的容量压力；这不是模型的原生语义容量，也不保证张量内的旧信息在预算用尽前不衰减或受干扰。

将上述规则和现有每轮重选卡片的策略保留为对照。先验证有余量时排名变化不引发换卡、已满但无必要写入时不换卡、确实放不下时从低到高腾位，以及未满时也能采纳明确更正；再在同一预算下盲评完整对话。此规则尚未在回放中实现或测量。

## 可盲测的最小对照（以下是预期方向，不是成绩）

| 不变的目标原话 | 上下文 A | 上下文 B | 人工预期 |
|---|---|---|---|
| “就按九点吧。” | 正在编一个不会执行的日程例句 | 正在确定今后每周一的交接时间 | B 的重要性更高；两者情绪均低。A 不能被写成真实日程 |
| “不用发了。” | 一张重复的预览图 | 刚谈妥的规则：未确认的草案今后都不外发 | B 高；必须引用对应上下文，不能把一回拒绝扩成长期规则 |
| “我等这一天等了好久。” | 在转述剧中台词 | 用户在讲自己刚收到的录取通知 | 不能把 A 当用户情绪；B 有自身事件和强度证据 |
| “以后寄到新地址。” | 平静确认永久迁址 | 同一真实迁址，兴奋地补充祝贺和感叹 | 迁址重要性都高；B 的情绪可更强，不因 A 平静而漏记 |

把配对关系、预期、未来问题留在评测侧。短夹具中的 `preferred` 是作者对哪些事项应留下的假设，不是真人评分。另有[跨窗口配对](../fixtures/state-window-pair-v1.json)：只改变开头对“真实约定/虚构示例”的说明，后面六轮保持一致；检查早先的语境是否影响了同一句“九点可以”的处理。

## 如何判断哪种方式更合用

1. **先问要留什么。** 在未见后续问题、策略名、模型分数或选卡前，让两位评审分别读截至当前的对话，在同一预算内标出想随手记住的事项，可留空或并列。要精确查的原话另标；退出工作记忆不要求删除档案。
2. **再问该不该用。** 在留出的相关轮、无关闲聊、更正和原话追问上，随机排列匿名回复。分别记录“自然沿用了有效约定”“无关却硬提旧事”“仍按被纠正的版本行动”“需要原话时查证、有出处”。允许两种都好、都不好或无差别。卡片不变只说明没有换卡，不证明回答没打扰人。
3. **按对话比较。** 单报相关轮和无关轮、两人分歧和持平，按整段对话而非逐 token 配对。样本足够时才给按对话重采样的区间。自然使用表现是选择策略的依据，未来问答答对率仅作次要指标。目前回放只测选卡和评级，不生成回复、不查档，未收集真人盲评。
