# 验证记录：state 更新与记忆行为试点

## 目标与证据边界

主要问题是固定权重下，不同 state 更新策略是否更符合人自然的记忆习惯：无查询时带着什么、旧约定更正后是否退出、长期线索能否跨过短窗口、无关对话是否影响记忆选择。正确率不是主验收项。目前也没有生成前台回答，因此“自然使用、主动打扰、按需回忆”均未实测。

本记录区分四层证据：规则单测只验证程序合约；随机张量探针只验证官方前向中的 state 因果通路；固定预训练权重回放观察这个小模型的标签读出和选卡；真人盲评才可能回答人类是否喜欢某种记忆行为。前一层不能替代后一层。

## 实际结果

| 试验 | 固定权重回放 | 本次实际观察 |
|---|---|---|
| 短对话 pilot | 官方 ChatRWKV x070 RWKV-7 0.1B；CPU fp32，PyTorch 2.15.0+cpu；4 个合成对话、13 轮；每轮工作卡预算 24 tokenizer tokens。候选卡文本、提及原文、事项归属和版本由夹具预先提供 | 三策略命中作者预设标签的条目数为 `read_only 4/13`、`replacement 3/13`、`feedback 2/13`；标签只是策展者假设，不能叫人类偏好成绩。评分缺项待评分别为 `9 / 9 / 11`。选卡不同的轮次分别为只读对重建 `1`、只读对反馈 `2`、重建对反馈 `1`。完整报告：[state-pilot-v2-cpu.json](../reports/state-pilot-v2-cpu.json) |
| 跨窗口配对 | 相同的最近六轮；只改变更早一句“真实年度约定 / 虚构台词” | 两个上下文、14 轮、6 个作者假设标签。三策略均命中 `0/6`，每策略有 10 次候选评估因 `X` 待评，工作卡写入总数为 0，所有选卡都为空。第 6 轮，“清单”重复强度在完整 state 和反馈 state 是真实约定 `4`、虚构情境 `1`；最近窗口重建则两边都是 `1`。这证明此例的 state 读出携带了窗口外差异，但其余维度仍不足，未形成可用卡。完整报告：[state-window-pair-v1-cpu.json](../reports/state-window-pair-v1-cpu.json) |

短 pilot 的其他信号同样有限：

- 四个无关轮中，选卡集合前后稳定的次数为只读 `3/4`、重建 `3/4`、反馈 `4/4`；同事项四维离散评级稳定次数分别为 `3/8`、`2/8`、`2/8`。这只描述候选卡与模型评级是否变动，不测回复会不会打扰人。
- 合成 deadline 案例中，旧值“周一九点”在第二轮只读臂入选，重建和反馈臂选择了大厅咖啡；到新时间“十点”后，反馈臂仍选咖啡，而只读和重建臂后来选到十点。这是值得人工复核的模型失误，不表示用户对策略的偏好或真实回复答错。
- 截止时间更正发生前，没有任何臂曾把旧截止卡写进自己的连续工作卡；因此先前版本卡移除数为 0。这个 pilot **没有**测到已经入卡的旧版本如何移除。
- `explicit_card_write_tokens` 只统计显式卡片 token 写入，不是总推理成本。报告另计模型 `forward_calls`、输入 token 和 appraisal 调用数；仍未测墙钟延迟或峰值内存。两策略的历史窗口、卡片重放次数不同，策略间差异不能只归因于循环 state 张量。
- 奖学金例子里，模型选了海报卡，没有选奖学金卡；小模型的四维离散评级没有可靠识别本例的重要性/情绪强度。这是模型与量表的失败信号，不能反推人的记忆偏好。

选择器以未舍入分数降序、事项 ID 字典序打破同分。短 pilot 的零分同分组在 replacement 有 `2` 组、feedback 有 `3` 组；ID 字典序会让有语义的 ID 决定 24-token 预算落到哪张卡。这是当前确定性政策的可见偏差，不得把平局选择包装成模型对内容的偏好或人类认可。回归审查还发现反馈臂原先只比较卡片集合，会漏掉集合相同但顺序变化；现在遇到该变化会从本轮真实对话边界按新顺序重建。两份固定权重回放中这种顺序变化计数均为 `0`，新路径由确定性单测验证。

候选记忆不是模型从聊天中抽取出来的：夹具提供候选卡、用户提及原文、事项映射和版本更正。当前只测给定候选后的 state 条件评分、排序与反馈，未测记忆抽取、归属、去重、版本识别或证据生成。

跨窗口配对只有两个合成情境。第 6 轮三个策略都未选卡，十项候选评级均有 `X` 待评；选卡一致只是三个空集合相同，不是策略表现相当。只读/反馈 state 对清单重复强度在真实情境读为 `4`、虚构情境读为 `1`，最近窗口重建两边均为 `1`。这是一次有限的窗口外状态差异读出，不代表它更符合人的习惯。

两份报告都记录 `live_replay_exact: true`，即在本次所测相同真实 token 序列上，含评分与不含评分的前台控制 state/logits 可精确重放。它不证明前台回答质量；本回放没有生成回答、没有查原文，也没有使用真实用户资料。`softmax` 标签概率和报告的 confidence 不是人类认同概率。

## 测试与随机权重探针

最终全套测试 **38/38 通过**，包括卡片顺序变化、同分审计和运行量计数回归。短 pilot 共 `414` 次模型前向、`57,713` 个输入 token、`72` 次候选四维 appraisal 调用；跨窗口配对为 `276` 次前向、`24,462` 个输入 token、`30` 次 appraisal。运行量包括 appraisal 提示和未评分控制重放，不是墙钟成本基准。随机初始化张量的固定上游 x070 state 分叉测试另见[历史原生 state 探针](../reports/native-state-branch.json)和[旧验证范围](LEGACY-RWKV-VALIDATION.md)。随机权重下改变 state 可以影响读出，只证明通路，不证明语义记忆。

## 真人盲评

[试标协议](HUMAN-RATING-PILOT.md)把“想保留什么”和匿名模型卡片组分开。评审先看 Phase 1，不看策略输出、模型分数和作者标签；完成并封存后才看 Phase 2。评审需独立填写，不能先讨论。

当前没有真人评分。试标包使用英文合成回放的中文意译，现阶段 Phase 2 仅收集工作记忆卡组偏好，不代表中文模型结果，也不评价自然回复、无关打扰或按需原文回忆。七个检查点中五题的三策略实际卡组完全相同或全空，只有两题能区分策略；不得按重复卡组臆测策略差别。

### 主验收：真人判断记忆使用行为

重建/替换与持续循环 state 的胜负，最终看哪种让人感觉助手更像自己会记、会更新、会在合适时候自然用起，而不是只看工作卡集合或正确率。留出成对对话轨迹，在相同底模与生成设置下比较匿名完整回复：

- **自然沿用与连续性：** 后续相关话题是否自然使用用户认为应随手记住的约定与偏好，而不是每轮都像失忆或机械复述卡片。
- **更正与替换：** 用户改口后，是否及时停止使用旧版本、采用新版本；分别记录到第一次正确采用和最后一次错误沿用之间的轮数。人工更正事件须独立标记，不能因旧值从未入卡而声称“旧卡成功淘汰”。
- **无关话题不打扰：** 在无关轮是否主动提旧事或把记忆硬塞进回复；以盲评整轮回复判断，不用“卡片未改变”代理。
- **按需回忆：** 用户问精确历史时是否只在需要时检索档案、给出可核对原文；未被问到时不泄露无关细节。
- **个人习惯契合度：** 评审独立先写会留什么、只待查什么、什么应退出，再对匿名策略完整对话给整体偏好，允许平局、“都不合适”与弃评，保留评审分歧。

报告以对话为单位汇总真人偏好及上述行为，不把跨轮样本当独立样本。回答准确率可作次要结果，不能覆盖自然度、时机、打扰感和用户偏好。当前这组小型合成回放只记录卡片选择和模型分级，未生成回复、未查档、未收集真人评分，故上述主验收**尚未测量**。
