# RWKV Priority Memory：先决定什么值得留下

**主要问题：重建 state 和持续循环更新，哪种更符合用户记事和用事的习惯？** 在没有问题提示的时候应留下什么；需要时能否自然沿用，不相关时会不会打扰；用户更正后能否改用新约定；问到原话时才去查档。问答分数是次要观察，不是选定策略的依据。首轮对照在固定权重的评估 state 上运行，不直接修改前台回复或网络权重。[状态更新与上游 PR 调研](STATE-INERTIA.md)

## 1. 一条约定走哪条路

用户平静地回答“就按九点吧”。如果上文问的是今天一件快结束的小事，它只影响眼前；如果问的是今后每周的交接时间，忘掉它会让以后的安排出错。词、语气、提及次数与时间都可以相同，**是模型看懂上文后给的重要性评级把两者区分开**。不需要等用户说“记住”。这是把人的自我判断作工程类比，不是意识、情绪识别准确率或模型自知的证明。

1. **归档（设计目标，未部署）。** 若用户授权，保存范围内的原话、角色、会话、消息 ID 与 UTC 时间；评分高低不决定原文是否存在。当前实验只用合成对话，SQLite 只是离线日志探针，不是获授权的真实对话档案或生产队列。
2. **自评。** 在当前 state 的独立副本上，由同一模型分别评重要性、用户表达的情绪强度、独立提及的强化程度、新近度。原文短引、用户轮数、时间戳由程序核对并提供。固定权重探针读标签概率，不生成理由；候选和版本更正由夹具给定。[量表与盲测例](APPRAISAL.md)
3. **更新评分和状态。** 新的独立用户提及更新证据计数和时间。固定权重回放对每个候选、每个维度从干净 state 分支读 logits；它不产生理由。反馈对照把选中卡写入评估 state，下一轮继承。评分提示不进入真实前台对话。本 pilot 的修正轮发生在旧卡实际选入之前，尚未实测已有旧卡的退出。
4. **日常作答（尚未实现）。** 工作记忆卡如何进入真实前台、换会话时如何重建、与模型原生对话 state 如何隔离，均未由当前评分回放验证。工作卡是外部文本，不是 RWKV 自身无提示记住。
5. **必要才回忆（设计目标，未实现）。** 如“上个月改时间时我说的原话是什么”，即使工作卡有“九点”，也不该据此编出原话。当前回放没有原文档案或检索路径，尚不能测试何时查档、查到什么或如何引用。

## 2. 首版可复核的保存分

下面是**候选基线，不是用户指定或实验拟合出的最佳参数**。采用正权重使任一主维度独立升高时，其他不变则保存分升高。分数不是事实真伪、用户喜好概率，也不是向量相似度。

| 分量 | 来源与拟定计算 | 明确排除 |
|---|---|---|
| 重要性 `I` | 当前回放使用 `模型上下文等级/4`；确定性排序 API 另支持显式下限，但固定权重回放不启用它。 | 置信度不另加一项；缺证据为待评，不伪造成 0 |
| 情绪强度 `E` | 事项所关联的用户表达强度，0–4 除以 4。高兴、悲痛皆可能很高；长期约定即使平静，也可有高 `I`。| 不按正负相抵，不以感叹号或助手的语气替代用户表达 |
| 重复提及 `F` | 模型结合 state、去重后的用户轮数和引文判断强化程度，等级除以 4。重复确认与否定旧说不能简单等价。 | 同一条消息内重复、助手复述、入卡、检索和重试均不加次数 |
| 新近度 `R` | 模型结合当前 state、评估时间和最后真实用户提及的 UTC 时间判断，等级除以 4。 | 重读不刷新时间；不使用固定半衰期替模型给分 |

`保存分 = 25 × (I + E + F + R)`。四项同权是实验起点；固定权重回放未设置显式下限。程序只合并分项，不额外按提及数或墙钟改分。同分按稳定 ID 排列；若模型普遍打平，入选结果不能归功于模型。[策略 JSON](../configs/priority-policy-proposal.json)

**同一件事如何认：** 初版用稳定主体、谓词、时间范围和版本 ID；“每周一九点交接”与“这周一临时十点”不是同一版本。用户连续改述可关联同一事项，每一原始用户轮最多计一次；明显粘贴/回放不算自发再提。不能确定是否同一件事时先不合并。语义抽取、跨轮同义合并、临时例外识别均待测；探针由调用方提供关联 ID，不能声称能自动理解这些句子。

**更正与审计：** 如“以后改十点，九点不再有效”，旧版本记 `superseded` 和生效边界，新版本重新计数，只让有效版本进入工作卡。若只是原约定的后果改变、事实本身没改，保留事项 ID，记录新证据并重评。同一版本取最近一次有依据的有效评级，而不是永远取历史最大自评分；旧快照留作解释。记录主体范围、消息/事项版本、事件及提及时间、各分量、显式下限、评估器/提示/策略版本、置信度、证据及总分。时间触发点和展示时间分开；选卡前以同一 `now` 重算，避免拿旧分比较新分。

## 3. 有限卡片和完整档案是两种存储承诺

| 层 | 平常怎么用 | 不保证什么 |
|---|---|---|
| RWKV live state | 逐步更新，回答当前上下文 | 不承诺有“可按事实寻址”的槽位，不能从中精确擦除某句话 |
| 高分工作卡（设计目标） | 正式系统预算尚未确定。当前合成回放为每轮 24 个模型 token，仅验证已编码卡片的排序/装入。 | 没有摘要器、真实服务预算、前台注入或按需检索实现；不得把提案预算当成测得的容量 |
| 原文与索引（设计目标） | 获授权的对话应独立落盘；索引是可重建的副本。 | 当前无真实对话归档或按需回忆实现；检索行为还不能声称达到此承诺 |

**回忆触发器的正反例（未来实验）：** 追问历史精确原话、日期或版本，或工作记忆缺历史证据时才查档；普通知识问题不搜索个人历史。具体检索预算、准确性和效率尚未测得，不设成已验证承诺。

**删除与恢复：** 用户撤回授权、要求忘记或设置到期时，阻止后续读取，清理原文、FTS/向量索引、卡片、快照、证据短引及待办；处置备份和残留，丢弃可能已受影响的 live state，仅以仍获授权的信息重建。明确备份清除周期，完成前不声称物理擦除。分数低只退出工作卡，不走这条删除路径。多主体隔离、端到端删除、真正的崩溃恢复是上线前硬门槛，不由合成单用户日志代替。

## 4. 研究依据和不能照搬的部分

- Anderson 与 Schooler 报告了人类记忆可用性与先前接触频率、新近度、接触模式的关系。[1] Mather 与 Sutherland 的理论认为唤醒会放大对高优先信息的偏向，并非任何激烈时刻的每个细节都更重要。[2] 这些依据用于选择和区分维度，不推出我们的权重与半衰期。
- **最接近的是 LUFY**：其重要性提示同时提供此前对话的摘要和本段对话，要求模型按对未来对话的用途打 1–10 分；情绪唤醒另行估计（§3.1、图 1）。[3] 会话结束后，遗忘步骤按综合重要性排序，以保留前 10% 的记忆条目为目标；条目数取整时实际比例略有偏差（§4.2、表 3）。[3] 本项目不以读语境打分为首创。我们的方案要求分数锚定具体事项和可核对的原话；分数决定哪些事项进入有限工作记忆，不按固定比例淘汰获授权的原文。
- Generative Agents 在创建记忆时用模型评分，检索时结合重要性、新近度、相关性。[5] MemoryOS 的热度计算含片段被检索次数、交互长度与近期性。[8] 我们把“用户主动再提”与“系统自己读过”分开，把无查询的保存排序与当下问题的相关性分开。
- Self-RAG 展示了按需检索而非一律检索的设计方向。[9] 此处门控不声称复现它的训练方法。LongMemEval 覆盖信息提取、跨会话及时间推理、知识更新和拒答，可用作次级问答评测，但不能单独验证保留排序。[6]
- RWKV-7 论文描述固定大小推理记忆；固定版 x070 参考代码第 143–146 行中，`state * w` 调已有矩阵，当前写入是独立的 `vk` 加项。[7][12] [旧单层实测](LEGACY-RWKV-VALIDATION.md)用空 state 时当步相同，非空下一步才出现差异。这不是能令指定事实“写得更深”的语义证据。首版不动内核；若研究这条线，须与“仅外部工作卡”在关检索时另做配对实验。

## 5. 实施次序与停走标准

| 阶段 | 交付与主要对照 | 继续条件（拟定，不是成绩） |
|---|---|---|
| A：确定性排序 | 四维逐项反事实，固定预算对比实际留下的 ID；重开 SQLite、时间推进、用户再次提及、助手复述及无效自评 | 所有合约测试通过；有日志可还原某条卡为何升降，低分不删档 |
| B：本地模型配对回放 | 比较只读完整 state、最近三个完整问答加当前用户话语的重建、持续反馈三种评估状态；另用窗口外早期语境配对。 | 检查实时弃评、选卡改变和评分稳定性。固定权重预跑是试点与错误探针，不以作者标签命中率判胜 |
| C：真人偏好与日常使用 | 两名评审先独立标注希望带入后续的事项，再对乱序匿名的真实生成回复评自然沿用、更正、无关打扰和按需查原话。按整段会话留出、保留分歧和并列。 | 选符合人类使用偏好的策略，而非为了 QA 分数挑样例。当前[试标包](HUMAN-RATING-PILOT.md)只有合成对话，尚无评审结果；不能据此宣布策略胜出 |
| D：回答与回忆开销 | 前台工作卡和按需查档路径实现后，再对同一会话评自然沿用、无关闲聊、版本更正、按需查询原话。 | 答案正确率仅作次要结果；主要看用户是否觉得记得合适、用得合适、不打扰。另报拒答、来源、查询、额外 token、P50/P95 延迟和显存 |

B 中评估器的作者标签、真人评审结果、未来问题和另一策略输出都不得进入模型评分提示。每次弃评、打平和证据不足单列；用人类标注检查缺失是否合理。当前固定权重模型对等级标签的概率不是人类同意概率，也不是 confidence calibration。真人偏好决定什么更符合日常使用；未来问答准确率次要，不能替代真实回答中的打扰、更正和按需查档体验。

**进度与证据边界：** [可复跑验证记录](VALIDATION.md)区分规则单测、随机权重控制、固定预训练权重回放和未做的真人盲评。[引用证据台账](../reports/sources.json)对应下面的来源。本地探针只使用虚构对话；正式部署、用户数据接入和推送不属于这次实验。
